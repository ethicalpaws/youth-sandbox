# CFI（控制流完整性）

## 分类
（1）Return-CFI（后向边缘 CFI）
在函数调用时压入安全标识符，返回时校验，防止返回地址被篡改。

- 优点：精准防御、轻量易部署。

- 局限：仅保护返回路径，无法防御前向控制流攻击。

（2）Function-Entry CFI（前向边缘 CFI）
限制间接跳转的目标必须是合法函数入口。

- 优点：实现简单、性能损耗极低。

- 局限：粗粒度校验，攻击者可跳转到合法但非预期的函数（如 Fn-ROP）。

（3）Type-CFI（细粒度类型校验）
基于 LLVM，校验函数指针的类型签名。

- 优点：防御 ROP 和类型混淆攻击。

- 局限：需编译器深度支持，性能损耗约 5%-15%。

（4）Intel CET
Shadow Stack（SHSTK）：维护一个受硬件保护的返回地址副本栈，返回时自动比对。

Indirect Branch Tracking（IBT）：强制间接分支目标以 ENDBR 指令开头。

- 优点：硬件级强制校验，几乎无法绕过。

- 局限：需 CPU、OS 及编译器全栈支持。


## CFI 的绕过思路
>CFI的防御强度依赖于控制流图的完整性。攻击者通过挖掘实现漏洞、利用未覆盖的执行路径或结合内存破坏漏洞，仍能找到突破缺口，这推动了更精细的防御技术（如Shadow Stack、MPX）的持续演进。

| 绕过方式 | 原理 |
|----------|------|
| 间接调用劫持 | 篡改函数指针，指向符合 CFI 校验的"跳板"函数 |
| 边界校验逃逸 | 利用整数溢出、地址截断等漏洞绕过校验 |
| 异常机制绕过 | 利用 SEH、信号处理等未被 CFI 覆盖的路径 |
| Fn-ROP | 利用 Function-Entry CFI 的粗粒度，直接调用合法函数组合攻击 |
| 类型混淆 | 利用 UAF 篡改虚表指针，绕过 Type-CFI |
| Endbr-Gadget | 搜索以 ENDBR 开头的 gadget，绕过 Intel CET 的 IBT |


## CFI 的价值与未来趋势
1. 核心价值
   - 显著提升攻击门槛，阻断控制流劫持。

2. 现实挑战
   - 性能与安全的平衡、静态分析不精确、无法防御所有内存破坏。

3. 未来趋势
   - 更精细的 CFI 校验（结合上下文）

   - 多层防御体系（CFI + ASLR + 栈保护 + 内存安全语言）

   - 软硬件深度融合（如 Intel CET）

   - AI 驱动的智能防御
