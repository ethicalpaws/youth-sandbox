# 缓冲区溢出

## 什么是缓冲区溢出？
程序在内存中分配了一块固定大小的空间（缓冲区）来存数据（比如一个长度为 10 的数组）。如果程序不检查输入数据的长度，硬要把 100 个字节的数据塞进去，多出来的 90 个字节就会“溢出”，覆盖掉相邻的内存区域（比如覆盖掉函数的返回地址）。黑客通过精心构造这 90 个字节，就能让程序跳去执行他们写的恶意代码。

## 缓冲区溢出概述
>目前，利用缓冲区溢出漏洞进行的攻击已经占所有系统攻击总数的80%以上。

□缓冲区溢出攻击之所以日益普遍，其原因在于各种操作系统和应用软件上存在的缓冲区溢出问题数不胜数，而其带来的影响不容小觑。
□对缓冲区溢出漏洞攻击，可以导致程序运行失败、系统崩溃以及重新启动等后果。
□更为严重的是，可以利用缓冲区溢出执行非授权指令，甚至取得系统特权，进而进行各种非法操作。
□如何防止和检测出利用缓冲区溢出漏洞进行的攻击，就成为防御网络入侵以及入侵检测的重点之一。

## 经典历史案例

**案例 1：2012年 - LuckyCat 攻击 (针对 Adobe Reader)**

    - 背景： 《纽约时报》报道的针对特定目标（尤其是日本）的高级持续性威胁（APT）攻击。

    - 攻击载体： PDF 和 RTF 文件。

    - 漏洞原理（SING表栈溢出）：

        黑客制作了一个恶意的 PDF 文件。

        这个 PDF 里嵌入了一种特殊的 TrueType 字体（TTF）。

        在字体的内部结构中，有一个叫 SING 表（用于存储字体特征）的区域。

        Adobe Reader 在解析这个表时，没有正确检查数据长度，导致恶意的超长数据写入了栈上的缓冲区，造成了栈溢出。

    - 结果： 只要用户用 Adobe Reader 打开了这个 PDF，黑客就能在用户电脑上执行任意代码，完全控制电脑。

**案例 2：2015年6月 - Lotus Blossom 行动 (针对 Windows 通用控件)**

    - 背景： 国外安全厂商发现的一个长期网络间谍活动，代号“莲花”（Lotus Blossom），主要针对东南亚、东亚等地区。

    - 攻击目标： Microsoft Windows 系统的通用控件（Common Controls）。

    - 漏洞原理（栈溢出）：

        Windows 系统里有很多标准 UI 组件（如按钮、列表框）。

        该漏洞存在于这些通用控件处理特定消息或数据的过程中。

        同样是因为没有对输入长度进行严格校验，导致栈溢出。

    - 结果： 攻击者可以通过发送特制的网络请求或诱使用户打开恶意文件，利用这个漏洞在 Windows 系统上执行远程代码，植入后门。

**案例 3：2017年 - PasswordStealer 木马 (利用 Microsoft Office 公式编辑器)**

    - 背景： 中国安全厂商兰云科技银河实验室发现的一批通过恶意邮件传播的木马。

    - 攻击载体： 恶意 Office 文档（通过邮件附件传播）。

    - 漏洞原理（公式字体名称长度未校验导致溢出）：

        恶意文档中嵌入了恶意的 OLE 数据（一种对象链接与嵌入技术），并在其中放置了恶意的 MathType 公式。

        当 Office 尝试加载并渲染这个公式时，会调用一个名为 EQNEDT32.exe（公式编辑器）的模块。

        这个模块在拷贝公式字体名称时，没有对名称长度进行校验。黑客构造了一个超长的字体名称。

        超长名称写入了栈上的缓冲区，造成了缓冲区溢出。

    - 结果： 木马成功执行任意代码，进而窃取用户浏览器、邮件客户端、FTP 软件中的密码等敏感信息。

## 缓冲区溢出的特性

**破坏性 (Destructive)**

缓冲区溢出一旦被成功利用，最直接的后果就是导致系统崩溃或数据丢失。

    原理： 缓冲区溢出会覆盖掉栈上的关键数据（比如函数的返回地址）。如果黑客只是随便写入一长串乱码，程序在试图返回时就会跳转到一个非法地址，导致段错误（Segmentation Fault），进程瞬间崩溃。

    后果： 如果这是一个服务器程序（比如 Web 服务器、数据库），它的崩溃就会导致服务中断，也就是我们常说的“服务器宕机”。

    如果黑客稍微高级一点，不写乱码，而是精心构造一段恶意代码（Shellcode）。这段代码执行后，可以调用操作系统的 API，执行诸如 rm -rf / 这样的删除命令，直接抹掉服务器上的关键数据。

**隐蔽性 (Stealthy)**

缓冲区溢出之所以难防，不仅因为它破坏力强，更因为它极难被发现

    - 漏洞发现前的“盲区”
      - 程序员在写代码时，往往假定输入是合法的、长度是可控的。他们很难穷举所有可能的恶意输入。所以，即使代码里有 strcpy 这种危险函数，只要没出事，程序员就会觉得程序是安全的。
      - 现代软件极其复杂，一个程序可能引用了大量的第三方库。底层的漏洞往往是由安全研究员、黑客甚至竞争对手发现的。编写者可能几年都不知道自己写的某行代码有溢出风险。
      - 因为不知道有漏洞，所以系统管理员不会去专门监控这种攻击行为，导致黑客可以长期、隐蔽地利用这个漏洞。

    - 攻击代码的“伪装”
      - 真正的黑客不会写几兆的恶意代码。他们通常只写几十个字节的“Shellcode”，这段代码唯一的作用就是：建立一个连接，下载真正的木马，然后运行它。这个过程可能只有几毫秒。在庞大的系统日志里，这几毫秒的异常流量就像大海里的一滴水，极难被监控系统捕捉到。
      - 攻击代码执行时，往往是在内存里悄悄进行的，不会产生大量的磁盘 I/O 或网络流量，传统的杀毒软件和入侵检测系统（IDS）很难实时拦截。
      - 高级的黑客在利用溢出时，会非常小心。他们不会让程序崩溃，而是会“修复”被破坏的内存，让程序继续正常跑下去。
      - 例子： 黑客覆盖了返回地址，跳去执行恶意代码，执行完后，恶意代码会再把返回地址改回原来的正确地址，让主程序继续运行。此时，用户和系统管理员完全感觉不到异常，以为一切正常，实际上后门已经被打开了。

    - 防火墙内部堂而皇之 (内部威胁)

      - 解释： 防火墙通常用来防御来自外部网络的攻击。但如果缓冲区溢出漏洞存在于内网主机上（比如公司内部的一台服务器），攻击者一旦进入内网，就可以利用这个漏洞在内网里“横着走”。因为内网通常被认为是“可信”的，防火墙不会拦截内网流量，这使得攻击者可以轻易获取原本无权访问的控制权。

    - 随机性和不可预测性 (防御困难)

      - 解释： 这是缓冲区溢出最狡猾的地方。黑客的攻击往往是“静默”的。在没有被攻击时，程序运行得好好的，没有任何异常。即使被攻击了，如果黑客技术高超（比如前面提到的“修复”内存），程序可能也不会崩溃。这种“不攻击时无异常，攻击时难预测”的特性，让传统的基于特征库的防御手段（如杀毒软件）很难提前拦截。

    - 漏洞的普遍存在 (防不胜防)

      - 解释： 缓冲区溢出漏洞不仅存在于老旧代码中，甚至存在于各种补丁程序里。这就形成了一个恶性循环：你为了修补一个漏洞去下载补丁，结果这个补丁本身可能又引入了新的缓冲区溢出漏洞。这种普遍性导致防御者永远处于被动状态。
