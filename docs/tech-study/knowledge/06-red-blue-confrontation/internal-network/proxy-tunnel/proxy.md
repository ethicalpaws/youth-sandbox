# 代理转发与隧道搭建
>隧道与代理转发本质上是同一类技术在不同语境下的称呼：它们都通过一个中间节点，将流量从源端“搬运”到无法直接访问的目的端。区别在于，代理侧重“代替你发起请求”，而隧道侧重“封装并传输原本无法直接通过的协议数据”


- 正向代理（Forward Proxy）：代理服务器代表客户端。你（客户端）无法直接访问目标，但能访问代理，于是让代理帮你访问。典型场景：翻墙、内网穿透中攻击机主动连接跳板机。

- 反向代理（Reverse Proxy）：代理服务器代表服务器。外部用户以为在访问代理，实际代理把请求转给了背后的内部服务器。典型场景：负载均衡、将内网服务暴露到公网（如 frp 的常规用法）。

## 常见代理方式

### ssh隧道

>SSH 不仅能远程登录，其端口转发功能是构建加密隧道的基石。它有三种模式：

- 本地转发 (-L)：将本地端口流量，通过 SSH 服务器，转发到 SSH 服务器能访问的远端目标。命令格式：ssh -L 本地端口:目标地址:目标端口 用户@SSH服务器。例如，通过跳板机访问内网数据库：ssh -L 3306:内网数据库IP:3306 user@跳板机。

- 远程转发 (-R)：将远端（SSH 服务器）端口流量，通过 SSH 连接，反向转发回本地。常用于把内网本地的服务暴露给外网的 SSH 服务器。命令：ssh -R 远端端口:本地地址:本地端口 用户@公网服务器。

- 动态转发 (-D)：在本地开启一个 SOCKS 代理端口。所有发往这个本地端口的流量，都会被 SSH 加密隧道送到远端，再由远端根据 SOCKS 协议的目标地址进行转发。这相当于把 SSH 服务器变成了一个 SOCKS 代理。


### 专用隧道/代理工具（适配复杂网络）
>当 SSH 不便使用（如目标无 SSH 服务、需穿越严格防火墙）时，这些工具更灵活：

- frp：经典的反向代理工具。需要一台有公网 IP 的服务器运行 frps，内网机器运行 frpc。frpc 主动连接 frps，将内网服务映射到公网端口上。支持 TCP、UDP、HTTP、HTTPS 等多种代理类型，也支持点对点（XTCP）穿透。

- Chisel：基于 HTTP/WebSocket 的隧道工具，用 Go 编写，单文件无依赖。流量封装在 HTTP 中，因此可以穿越仅允许 Web 流量的防火墙或 CDN。支持 SOCKS5 代理和端口转发，且内置 SSH 加密保护。

- Neo-reGeorg：针对 Web 环境的隧道。将脚本（如 PHP/ASPX）上传到目标 Web 服务器，攻击机通过该脚本建立 SOCKS 代理。适用于目标只开放了 Web 端口（80/443）的场景。

### 内网多级级联（穿透多层网络）
>在渗透测试或复杂内网环境中，往往需要穿过多个隔离区。以经典工具 EarthWorm (EW) 为例，它通过组合不同模式实现级联：

- 基础转发：lcx_tran（监听本地端口并转发到指定地址）或 lcx_slave（主动连接远端并转发）。

- 多级串联：将多个转发进程串联，例如将本地 SOCKS 服务端口，通过两跳甚至三跳转发，最终引出到公网。EW 的 ssocksd 用于开启正向 SOCKS，rssocks 用于反向 SOCKS，配合 lcx_* 系列可构建复杂链路。

### 场景选择

| 场景 | 推荐方案 | 理由 |
|------|----------|------|
| 临时访问内网数据库/服务 | SSH 本地转发 (-L) | 命令简单，加密安全，无需额外部署 |
| 把本地 Web 服务临时给外网看 | SSH 远程转发 (-R) 或 frp | SSH 临时可用；frp 适合长期稳定使用 |
| 需要一个全局代理来扫描内网 | SSH 动态转发 (-D) 或 Chisel | SSH 原生支持；Chisel 在 HTTP 受限环境更强 |
| 目标仅开放 Web 端口 (80/443) | Neo-reGeorg | 隧道流量伪装成正常 HTTP 请求 |
| 穿透多层内网隔离 | EarthWorm 级联 或 多级 frp/Chisel | 可组合出多跳链路，适应复杂拓扑 |
